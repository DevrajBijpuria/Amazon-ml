# Phase 2.5 Report: Hardening the Phase 2 Baseline

Generated by `phase2/src/phase2_5_report.py` from `phase2/artifacts/phase2_5/`. Scales: **dev** = 5,000 Source-1 entities against 100,000 target records per source (the Phase 2 development setting); **10k** = 10,000 Source-1 entities against the complete Source-2 (5.03M) and Source-3 (5.29M) files; **50k** = 50,000 Source-1 entities against the complete target files. Every comparison within a scale uses identical validation Source-1 entities (20%, seed 42). Confidence intervals are 95% percentile bootstrap intervals over validation entities (B = 1,000, numpy seed 42, paired across configurations).

## 1. Executive Summary

**Both blocking and the classifier limit performance at full scale, and the classifier limits it more.** On 50,000 Source-1 entities against the complete target files (10,000 identical validation entities), the unchanged Phase 2 baseline B0 reaches macro F0.5 0.8772 [0.8727, 0.8813], not the 0.9709 of the development setting: its candidate recall falls from about 98.1% on 100,000-record target pools to 91.25% on the full files, and its logistic regression misses 4,357 retrieved positives while making 1,353 false merges.

The frozen hardened configuration scores **0.9309 [0.9279, 0.9340]** at threshold 0.8, a paired improvement of +0.0537 [0.0497, 0.0577] over B0. Improved blocking alone (B0's logistic regression on the new candidate set) raises candidate recall to 95.25% and macro F0.5 by +0.0067 [0.0041, 0.0090]; replacing the model with gradient boosting on the same candidates adds the rest (+0.0471), cutting false positives from 1,427 to 916 and classifier misses from 5,350 to 2,872. Blocking still loses 1,604 validation positives, the ceiling Phase 3 inherits.

B0 was reproduced byte-for-byte before any change and again on the final code; every comparison uses identical validation entities, seed 42 and paired bootstrap confidence intervals; no improvement is credited from a lower-recall candidate set (the frozen candidate set has higher recall than B0). Test data has not been used for any choice: after the configuration was frozen, a development-scale smoke test ran test inference on a 5,000-entity test subset only to check that the frozen pipeline runs end to end and passes the validator; no labels exist for test, nothing was changed afterwards, and no Phase 2.5 result reads its output.

## 16. Remaining Limitations

- Blocking still misses 1,604 of the validation positives at 50k (candidate recall 95.25%); at 10k most B0 misses were suppressed high-frequency keys (453 of 600), and the no-cutoff diagnostic shows up to 99% of positives share some key, so the remaining recall sits in buckets too large to enumerate.
- The classifier still misses 2,872 retrieved positives and makes 916 false merges on 10,000 validation entities; recall (0.8706) remains the weaker side.
- The per-S1 cap ranks by the number of retrieving rules and edit similarity; adding rules can push true pairs out of the cap (observed for name_phonetic_token), so any new rule must be evaluated after the cap.
- Cross-script and transliterated names are only partly recovered by deterministic romanization and the consonant skeleton; the per-token phonetic block did not help at full scale.
- Validation macro F0.5 is selected and reported on the same validation entities (the Phase 2 protocol); the threshold curve is flat around the optimum, but a small optimism remains.
- France appears only in the test set; it is handled by the same country-agnostic rules without training examples.
- All Phase 2.5 measurements are on Source-1 samples (5k to 50k); the full-scale figures are projections until the full run is executed.

## 17. Phase 3 Handoff

- Start from `phase2/config/phase2_5_frozen.yaml` and the frozen code; reproduce `phase2/output/phase2_5/frozen_50000/` (macro F0.5 0.9309) before changing anything.
- Largest remaining lever on the blocking side: selective composite keys for oversized buckets (for example a rare name token combined with a locality token) instead of skipping them, evaluated after the cap.
- Largest lever on the model side: more training entities than 40,000 and features that separate near-duplicate businesses at the same address; gradient boosting hyperparameters were deliberately not tuned.
- Keep the evaluation protocol: identical validation entities, seed 42, paired bootstrap, recall reported alongside every F0.5.
- The full Source-1 / full target run and the test submission are pending the user's approval (runtime and memory projection in section 13).
